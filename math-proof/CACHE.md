# 缓存前缀纪律（math-proof preset）

> 依据：本项目 Reasonix 文档的实测经验（`DeepSeek-Reasonix/docs/compaction-cache-tools-freeze-20260831.md`、
> `research/cache-aware-compaction-design.md`、`deepseek/guides_kv_cache.md`、`qwen/context-cache.md`）。

## 一、缓存怎么工作（三条硬事实）

1. **缓存单元 = 完整前缀**：`system` + `tools` + `messages` 一体，按**完整前缀单元**命中。
   前缀里任何一处字节漂移，就从漂移点之后全部失效。
   - 实证：只冻结 `messages` 不冻结 `tools`，命中率从 97.5% 掉到 system-only（6.6%）。
2. **工具定义参与缓存计算**：工具**列表顺序 / 字段顺序 / 字段结构**必须完全一致；
   只改 schema 不改描述，同样打穿。
3. **重复内容放开头，差异内容放末尾**：稳定前缀 + 追加式增长是唯一正确形态。
   `A+B` → `A+B+C` 命中；`A+B` → `A+C` 不命中（只可能命中公共前缀 `A`）。

另外两条运维事实：缓存是**尽力而为**（不保证 100%），**几小时到几天**不用会自动清空；
首次重复重放命中率是渐进的（40–68% → 99.6%），不是 bug。

| 纪律段（`proof-discipline`） | ✅ | 静态 |

## 三、纪律（违反就是全价）

1. **前缀必须字节稳定**：persona / 纪律段 / 工具描述 / 工具 schema 里**禁止**出现
   运行时时间戳、随机数、pid、临时路径。固定日期（如「2026-09-09 实测」）不算易变。
   机器守护：`tests/cache-check.mjs`（跨进程指纹一致 + 易变内容扫描）。
2. **改插件 / 技能 / persona = 打穿所有会话的缓存前缀**（一次全价）。
   长程会话中**批量改**，改完**开新会话**，不要在会话中途零散改。
3. **只追加，不改写历史**：工具输出进 messages 后不再回改；需要新信息就再调一次工具。
4. **工具输出有界化**：`proof_dag` 的表格 40 行、拓扑序 60 行上限，超出写「另有 N 条」+
   台账路径。**这不是删数据**——完整内容在 `~/.dsh/state/math-proof/dag-*.json` 里。
5. **压缩（compaction）会改写前缀 → 缓存必冷**：不要把压缩当免费操作。
   跨天续接优先走 `proof_dag brief` + 新会话（台账是事实源），而不是依赖长上下文。
6. **技能索引顺序是 harness 保证的**：`dsh-skill-filesystem` 对根目录条目
   `sort((a,b)=>a.name.localeCompare(b.name))`（`lib/index.js:584`）。
   若未来该行为改变，`cache-check` 的跨进程指纹检查会立刻报警。

## 四、什么时候值得在意

前缀约 1.5–2 万 token，远超最小可缓存长度（1024 token），**每一轮都命中就是每一轮省钱**。
反之，前缀每轮漂移一次，就退化为「只命中 system 前缀」——这正是文档里 9 次摘要
命中 13.45%、分子恒等于 system 大小的情形。

## 五、实测：稳定后的命中率与费用结构（2026-09-09）

数据源：`~/.dsh/sessions/**/session.jsonl.zstd` 的 usage 事件（1 532 步）。工具：
`node scripts/cache-report.mjs`。

| 指标 | 实测 |
| --- | --- |
| 缓存命中率 | **98.6%**（命中 399.7M / 未命中 5.65M） |
| 命中率分布 | ≥95% 的步占 92%；<20% 仅 16 步 |
| 费用三段 | 命中 7.99 元（48%）+ 未命中 5.65 元（34%）+ 输出 2.95 元（18%）＝ **16.60 元** |
| 输出中推理占比 | 46.6% |
| 上下文中位 / P90 / 最大 | 214k / 587k / 792k |

按 preset 拆分：

| preset | 步 | 命中率 | 费用 | 占比 |
| --- | --- | --- | --- | --- |
| standard（开发会话） | 1 147 | 98.8% | 13.72 元 | 83% |
| cordis | 291 | 96.9% | 2.03 元 | 12% |
| **math-proof** | **94** | **98.1%** | **0.85 元** | **5%** |

**结论**：缓存本身没问题（命中 98.6%）。贵的原因是两件事：
1. **未命中价是命中价的 50 倍**（1.0 vs 0.02 元/M），所以 1.4% 的未命中吃掉 34% 账单；
   其中 **7 步单步未命中 ≥200k 就占了全部未命中的 53%**——正是「大上下文里改配置 / 冷启动」的时刻。
2. **上下文 × 步数**：命中价再低，399M 命中 token 也是 8 元。standard 会话上下文中位 310k，
   math-proof 只有 116k——**会话越瘦越便宜**。
