# long-horizon-discipline：长程证明任务纪律

## 0. 一句话

**长程任务不是「一次性问答的放大版」，而是「阶段交付 + 可接手证据 + 不断链的依赖图」。**
上下文会压缩、进程会重启、人会换班——**台账必须能独立重建「现在在哪、下一步做什么、什么被卡住」**。

## 1. 五个阶段与交付物

| 阶段 | 产出 | 硬性证据 |
| --- | --- | --- |
| 1 探索 | 参考方向、文献来源、候选陈述 | `journal(kind:"source")`，精确到 `文件:行` |
| 2 架构 | **蓝图**：定义层 → 引理层 → 主定理（先写结构，不写证明） | `proof_dag add` 全部节点 + `source` |
| 3 依赖图定稿 | 无环、无悬空、每节点可判定 | `proof_dag check` 断链清零 |
| 4 逐节点证明 | 每节点一个证明项 + 编译证据 | `proof_compile` exit 0 + `proof_audit` 合规 |
| 5 审计与记忆 | 缺口声明、待裁决、交接 | `journal(kind:"milestone"/"handoff")` |

**阶段之间不许跳步**：蓝图未定就写证明 = 返工；依赖图未定就跑并行 = 重复劳动。

## 2. 跨天接手协议

1. 新会话 / 新一天**第一件事**：`proof_dag action:"brief"`。
2. 按简报顺序处理：**待人类裁决 → 环/悬空/断链 → 无证据的 proven → 未诊断的失败 → 复核 needs_review → 派发可开工节点**。
3. 一次只做一个节点；做完立刻 `update` 写 `evidence`，**不要攒着最后一起记**（上下文一压缩就丢）。
4. 收工前写 `journal(kind:"handoff")`：今天做了什么、卡在哪、明天从哪开始、有无待裁决。
5. 决策与来源进 `journal`，**不要只留在对话里**。

## 3. 依赖图设计原则（经得起考验）

- **节点必须可判定**：写「可验证命题」，不写「证明 X」。不可判定的节点拆到可判定为止。
- **单入口**：一个主目标（无下游依赖的节点），其余都是它的支撑。
- **无环**：`check` 报环即停工修环，拓扑序不可定义时一切调度都是假的。
- **纸面依赖禁止**：声明 `deps` 就必须在源码 `import` 对应模块；`check` 的「台账↔代码断链」必须清零。
- **签名变更即级联失效**：改 `statement`/`deps` 后，该节点与全部下游自动退回 `needs_review`——**不要手动跳过复核**。
- **失败要分诊**：`statement_wrong`（改形式化，别硬证）vs `proof_too_hard`（拆子引理）。未诊断的失败是负债。
- **证据不可省**：`proven` 必须带 `evidence`（编译 exit 0 / 0 postulate），否则只是声称。

## 4. 向人类学者学习（而不是抄结论）

- 每个关键命题带 `source`：文献 / 定理名 / 人类学者策略，**精确到文件:行**（如 `T6.agda:1065`）。
- 学的是**方法与结构**：他们怎么选定义、怎么分层引理、怎么避开退化情形。
- 文献结论**不可直接当证明**：文献转述 = 猜想；必须自己过三筛 + 形式化。
- 人类学者与代码冲突时：`journal(kind:"decision", open:true)` 请人类裁决，**不擅自选边**。

## 5. 构造主义与反暴力（红线）

- **计算 / 搜索只做三件事**：找反例、生成猜想、给有限穷举提供**完备性论证**。
- **不得**把「枚举到没找到反例」当证明；不得把 >27 case 的穷举当构造性证明（必须符号化：let-free + 基展开）。
- **不得**用 `refl` 暴力求值冒充构造（`refl` 只确认定义自洽）。
- 优先**构造 witness**（给出算法/结构），而不是「假设存在」。
- 离散基座优先：判为连续统病态就换基座，不要在连续统里堆证明。

## 6. 证明器限制 → 软件经验

- 撞到工具链限制，先 `prover_limits query "<报错原文>"`；`proof_compile` 的指纹表会直接给出「经验库: <id>」。
- 确认是新限制 → `prover_limits add`，**`evidence` 必填**（日期 + 命令 + 结果）。
- 区分「限制」与「错误」：`InfectiveImport`、`-M6G` 误杀、沙箱 exit 42 是**限制**，不是你的证明失败。
- 限制是**可累积的软件经验**：修的是流程与工具，不是把限制写进 postulate。

## 6.5 策略经验：什么时候用什么（本项目实测）

工具链限制有 `prover_limits`、Python 可复用件有 `proof_oracle action:"kit-list"`（库 `oracle_kit`），**证明策略**过去没有沉淀——这是最大的空白。
每条按「症状 → 判据 → 做法 → 证据」记；项目内用 `proof_dag journal(kind:"lesson")` 落台账。

| 症状 | 判据 | 做法 | 证据 |
| --- | --- | --- | --- |
| 连续多轮编译、每轮只改一处，仍失败 | 怀疑**陈述为假**，而不是证明难 | 先跑 oracle 结构穷举找反例（≤1 分钟），**不要继续改证明** | NSE `Δf ≡ 0` 在线性场抽样下「成立」，在 729 点 δ 基上被否证：`laplacian(δ₀)(e₀)=2` |
| 小样本/线性场/少量随机点上恒等式成立 | **抽样会骗人** | 换成结构基（δ 基 + 常数场）穷举，并在 `manifest` 里写清 `domain`/`points` | 线性场 `f = xᵢ` 上 `Δf ≡ 0` 恒成立 → 抽样会给出假阳性 |
| 论域有限但 case 数 > 27 | 穷举会变成暴力计算 | 符号化：let-free + 基展开（`Semilinear`/`Linear` + `ext3`），把「两映射相等」降为「基上相等」 | 纪律 §2 策略优先级 |
| 改一行要等很久 | 编译面太大 | 待证引理先放**探针模块** `_Probe*.agda`（只 import 必要模块）；改 `Base/Trit.agda` 会让 300+ 下游接口失效 | 实测：探针 2.83–2.92s vs 主模块分钟级 |
| 同一模块编译失败 ≥3 次 | 策略问题，不是能力问题 | **换手**：按 `agda-proof-engine` §5.9 协议批量修复（若环境存在 `loop-engineer` 技能亦可委托它，它不随本仓库分发），或换证明范式（穷举↔代数链↔结构实例化） | `proof_compile` / `check` 的编译预算闸门 |
| 上游引理陈述可能还要改 | 下游全部作废 | **先定依赖图再写证明**；改 `statement`/`deps` 后下游自动 `needs_review` | blueprint refinement 级联 |
| 反例路线还没回来就开始写正式证明 | 发现模式与形式化模式混用 | 反例判定未落定前不写证明项 | 本次 NSE 会话：顺序做反 → 十几轮编译白做 |

**记法**：项目内 `journal(kind:"lesson", text="症状 → 判据 → 做法 → 证据", source="…")`；
跨项目、可复用的教训写进本表（或 `prover_limits` / `proof_oracle action:"kit-add"` 的对应条目）。

## 7. 记忆分层（别把所有东西塞进上下文）

| 层 | 存什么 | 位置 |
| --- | --- | --- |
| 台账 | 节点、依赖、状态、证据、诊断、溯源 | `~/.dsh/state/math-proof/dag-*.json` |
| 流水 | 决策、来源、限制命中、阶段、交接 | 同上（`journal`） |
| 经验库 | 工具链限制与规避 | `~/.dsh/state/math-proof/prover-limits.json` |
| 项目记忆 | 结论、裁决、跨任务知识 | 仓库 `memory/*.md` |
| 代码 | 唯一裁决 | `src/**/*.agda` |

**代码 > 文档**：文档与代码冲突，以 Agda 源码为准，并把冲突记成待裁决项。
